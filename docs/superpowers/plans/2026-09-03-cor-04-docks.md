# COR-04 Dock Definitions and Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build configuration-backed dock definitions, cargo compatibility, and reservation ownership without implementing docking execution.

**Architecture:** `DockFactory` converts validated level dock blocks into immutable `DockModel` definitions. `DockSystem` owns the model's reservation and occupancy mutations, while `ShipModel` owns a serializable cargo manifest. No position transformation or docking movement is introduced.

**Tech Stack:** TypeScript, Node test runner, existing validated frozen configuration source.

**Spec:** `DEV Backlog v1.5`, Complete Design Bible v1.5 sections 3.5, 3.6, 10.4, 22.3.

## Global Constraints

- Do not change `Port_Control_Baseline_Source_FINAL_v1.5`.
- Do not implement COR-05, DockingController, snap movement, state transitions, CargoSystem, or UI.
- Dock coordinates are authored point-like world coordinates with no offsets.
